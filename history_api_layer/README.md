# history_api_layer — изолированный прототип этапа 2А

Проект: **MOEX_HISTORICAL_LAB_2Y**. Этап: **2А — один логический read-only
запрос к T-Invest History API (SBER, год 2025, 1M, годовой ZIP-архив)**.

Режим: `RESEARCH ONLY / READ ONLY / NO LIVE ORDERS / EXISTING PIPELINE
UNCHANGED / ADDITIVE IMPLEMENTATION ONLY / NO OVERWRITE / NO MASS DOWNLOAD`.

Каталог **новый и независимый**. Ни один существующий файл лаборатории
не изменён и не импортируется; торговые методы API не используются;
подключения к торговому роботу нет; ордера не создаются; LIVE-счета
не используются.

## Структура (каноническая)

Все файлы прототипа лежат **внутри** каталога `history_api_layer/`
репозитория (не в корне репозитория). При публикации в GitHub-репозиторий
каталог переносится целиком, с сохранением имён:

## Запуск

```bash
cd MOEX_HISTORICAL_LAB_2Y/history_api_layer

# 0. Тесты (без сети и токена)
python -m pytest tests/ -q

# 1. Загрузка одного ZIP (требуется токен в окружении)
export TINKOFF_READONLY_TOKEN='...'   # значение НЕ передаётся в логи и URL
python fetch_archive_zip.py --year 2025
# вариант с FIGI (deprecated для instrument_id, план 1.1) и явным значением:
python fetch_archive_zip.py --year 2025 --id-type figi
python fetch_archive_zip.py --year 2025 --id-type uid --id-value e6123145-9665-43e0-8413-cd61b8aa9b13

# 2. Инспекция структуры загруженного архива
python inspect_zip.py --zip data/raw_zips/SBER_2025_uid.zip --year 2025 --full

# 3. Проверка идентификаторов и нормализация
python normalize_ids_fields.py --zip data/raw_zips/SBER_2025_uid.zip --year 2025

# 4. Отчёт пригодности для 1M -> 5M
python report_suitability_5m.py \
  --normalized "data/normalized/SBER__e6123145-9665-43e0-8413-cd61b8aa9b13_2025_SBER_2025_uid.normalized.csv" \
  --year 2025
```

## Учёт HTTP-вызовов (P3, важно)

Один запуск `fetch_archive_zip.py` — это **один логический запрос**
(один архив за один год), но **не обязательно один физический GET**:

- максимально возможное число GET-попыток за запуск:
  `len(HISTORY_ENDPOINTS) × MAX_HTTP_ATTEMPTS` = **2 домена × 6 попыток = 12**;
- повтор выполняется **только** при HTTP 429 (уважение `Retry-After`;
  пауза по умолчанию 5 с, потолок 60 с) и учитывается в счётчике попыток;
  бесконтрольного повторения нет: лимит попыток на домен исчерпывается,
  затем запускается следующий домен;
- 404 — невозвратный статус: немедленная фиксация кандидата `absent_404`
  без повторов и без перебора второго домена;
- self-limit лаборатории: 20 запросов/мин (скользящее окно, мьютекс) —
  это СОБСТВЕННОЕ ограничение прототипа, **не** лимит API;
- фактические счётчики каждого запуска — в мете:
  `http_requests_max_possible`, `http_requests_made`, по-попыточно
  `attempts[].url`/`attempts[].status` (токен в URL и мете отсутствует).

## Безопасность

- Токен берётся **только** из переменной окружения
  `TINKOFF_READONLY_TOKEN` (тот же безопасный источник, что и у
  существующих диагностик лаборатории). Значение токена никогда не
  печатается, не логируется, не попадает в URL и в отчёты — мета содержит
  только факт наличия (`token_available: true/false`). Authorization
  передаётся исключительно заголовком `Bearer`.
- При отсутствии токена реальный GET **не выполняется** (fail-closed);
  создаётся честная запись `executed=false` с причиной.
- Единственный сетевой вызов — `GET /history-data` (рыночные данные).
  Статический тест `tests/test_no_trading_calls.py` запрещает любые
  торговые эндпоинты и модифицирующие HTTP-методы; тесты
  `tests/test_fetch_url.py` перехватывают `urllib.request.urlopen` и
  проверяют фактический метод (GET), URL (параметры) и отсутствие токена.
- `NO OVERWRITE`: существующие файлы не перезаписываются (исключение
  `NoOverwriteError`; повторная загрузка ZIP требует явного
  `--allow-overwrite`). Запись всегда `tmp+rename` в том же каталоге.
- Все результаты сохраняются только внутри `history_api_layer/data/`.

## Границы этапа 2А (важно)

2А подтверждает **только** группу «структура и статика архива» одним
логическим запросом (план, раздел 12). Суточное обновление — этап 2Б;
retry/429-механика — этап 2В. Заявлять «один GET подтвердил всё» —
нарушение протокола; и наоборот, один запуск — это до 12 GET-попыток
(см. раздел «Учёт HTTP-вызовов»).

Что 2А **не** делает (запрещено расширять объём самостоятельно):
TOP-10, несколько лет, GetCandles, агрегация 5M в общий пайплайн,
интеграция в старый пайплайн, массовые загрузки.
